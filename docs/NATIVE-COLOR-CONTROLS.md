# Native color controls and visibility export

Implemented October 9, 2026 in the development source.

The color wheel remains available. Open **Fine-tune color** beneath a channel to
enter native Hue, Saturation, Brightness and Contrast values. Empty fields retain
the wheel's calculated value, or the original material value if no wheel color is
selected. Apply appearance/equipment to rebuild the preview. Values are absolute
Blender controls, not relative adjustments. Choosing another wheel color or using
its Reset clears that channel's fine-tuning; Reset fine-tuning retains the swatch.

Buttons and keyboard arrows step by 0.1 while retaining manually typed precision.
Blank fields display the applied preview value; arrows use that value as their
starting point. Apply a wheel change before fine-tuning so the preview value is
current. Older previews without palette metadata use native defaults as a
fallback until regenerated. Only included equipment components appear in the
piece selector. Whole-item/layer editing has been removed; legacy stored colors
continue to work with their original per-piece override precedence.

Native ranges: hue 0–1, saturation 0–1, brightness −1–1, contrast 0–3.
Saturation is inverse: 0 is strongest, 1 is grayscale. These are SWTOR shader
parameters, not conventional HSV values. They preserve texture detail and masks.
Optional `primaryPalette` / `secondaryPalette` objects are saved beside existing
hex colors; older presets remain valid. Effective numeric values are exported to
the standard `palette1` / `palette2` arrays. Viewer-specific keys are removed.
Unsupported material channels produce an error instead of silently dropping edits.

## Why Dak's red chest looked orange

The old picker calibrated against the median of the entire palette image. The
chest's primary dye region has a different baseline from its background and trim.
For `chest_capetight_heavy_jk_a10c03_u_h.dds`, red produced hue 0.9472937 from the
whole image; 162,141 strongly primary-masked samples produced 0.8980639. The latter
closely matches the user's manually chosen Blender hue 0.900.

Garment calibration now samples strong primary R / secondary G mask regions
independently. If no strong samples exist, it tries pixels dominated by that
channel; empty or mismatched-size regions retain the previous estimate. Skin,
eyes and hair retain their existing calibration because their masks differ.
Brightness is still an estimate; AO, gamma, mask blending, texture variation and
lighting affect the final visible color. This is not a promise of exact RGB pixel
matching or identical Blender/viewer lighting. Native controls provide explicit
fine-tuning without replacing the shader or rendering pipeline.

The shader equations were checked in the installed GR2 `types/node_group.py`
(HuePixel, OffsetSaturation, AdjustLightness) and against the matched GR2 4.2.1
package used by ZG Tools 2.0.14. No upstream shader code was copied or modified.

## Visibility export

The renderer now supplies the applied preview's object-name → source-model and
equipment-layer mapping to ZG export. Hidden geometry is matched to its actual
source, avoiding assumptions about names generated by a GR2 importer. Head and
helmet remain independent; hidden helmet slots also lose their gear-name entry.
Hidden flags for parts absent from the current preview are ignored, matching the
viewer after removing/replacing equipment. Present parts that cannot be mapped,
unknown names without a preview mapping, and partial hiding of a multi-mesh
source remain explicit errors.
Gear names are assigned after visibility is resolved, so a fully hidden layer
cannot conflict with the visible layer's name. Source mappings are indexed once
per export. Palette/mask texture pairs are decoded once for both dye channels;
the image cache retains at most two decoded textures.

The supplied original DakRedux2 preset succeeded in direct tests with the head
shown and both helmet pieces hidden, before this change. Thus the screenshot's
exact failure is not reproduced from that file. The source-mapping change covers
name differences; the requested failing saved state is still needed to establish
its precise cause.
